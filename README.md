# Portfolio

This project essentially outputs the contents of a grocery list. If you select menu option 1, you can search for an item and the program will tell you how much of that item exists. If I search "Yams" it will output 5 yams total. However, if I search "Bananas" it will tell me there are 0 bananas. 
Menu option 2 will output the entire grocery list with the totals for each product, including any empty products I may have added to the list.
Menu option three will output the whole grocery list as a histogram with the numbers being represented by asterisks (*). 
menu option four will back up the new list into a separate file and close the menu. 

I think the part I did particularly well was the menu functionality. I wanted it to continue to run UNTIL you exited, rather than performing a task and quitting. I also wanted you to be able to use all of the menu options before quitting, some of them even multiple times. 

I'm not sure what I could do to ENHANCE my code, besides extending menu option 1 to also allow you to add a new product WITH a new amount so you could output 5 bananas, for example. Also allowing menu 1 to read non-plural input, like "yam" instead of "yams," and finally, truly any input that is not 1, 2, or 3, will prompt the exit menu which is something I could've fine-tuned to output an error statement. It just would've looked cleaner and more professional. 

I think overall the project was evenly difficult. Each menu option was simply, "OK take the last one now add something new to it." So honestly I was decently challenged with each new menu. I followed a Maps tutorial on YouTube to help me grasp the concept better, and I scrolled W3Schools when I needed to remember some of the resources I had available to me.

This program taught me to take it one step at a time. I have a habit of skipping around my code and working on the big picture before getting down to the nitty-gritty details and that's just not how programming works. So this helped me to learn that I should finish step 1 before working on step 2.

I made this program maintainable, readable, and adaptable by including plenty of inline comments and working hard to make my code as succinct as possible, so as not to overload the page with extra lines of code if possible.
