# CS-210-Programming-Languages-or-Object-Oriented-Programming

This project essentially outputs the contents of a grocery list. If you select menu option 1, you can search for an item, and the program will tell you how much of that item exists. For example, if I search "Yams," it will output 5 yams total. However, if I search "Bananas" it will tell me there are 0 bananas. 
Menu option 2 will output the entire grocery list with the totals for each product, including any empty products I may have added to the list.
Menu option three will output the whole grocery list as a histogram with the numbers being represented by asterisks (*). 
Menu option four will back up the new list into a separate file and close the menu. 

I think the piece I did particularly well on was the menu functionality. I wanted it to continue to run UNTIL you exited, rather than performing a task and quitting. I also wanted you to be able to use all of the menu options before quitting, some of them even multiple times. 

To enhance my code, I would extend menu option 1 to allow you to add a new product with a new amount, so, for example, you could output 5 bananas. I would also make a change to menu 1 to read non-plural input, like "yam" instead of "yams." Finally, any input that is not 1, 2, or 3, will prompt the exit menu, which is something I could've fine-tuned to output an error statement. I think these small changes would make the output cleaner and more professional. 

Overall, the project was equally difficult. Each menu option was simply, a case of taking the last iteration and adding extra functionality. I followed a Maps tutorial on YouTube to help me grasp the concept better, and I scrolled through W3Schools when I needed to remember some of the resources I had available to me.

This program taught me to take it one step at a time. I have a habit of skipping around my code and working on the big picture before getting down to the nitty-gritty details and that's just not how programming works. So this helped me to learn that I should finish step 1 before working on step 2.

I made this program maintainable, readable, and adaptable by including plenty of inline comments and working hard to make my code as succinct as possible, so as not to overload the page with extra lines of code if possible.
